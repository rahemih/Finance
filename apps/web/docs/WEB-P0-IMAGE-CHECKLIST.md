# NEXUS QUANT — چک‌لیست مرکزی تصاویر WEB-P0

## گزارش وضعیت

- تصاویر مرجع Google Docs: **212/212 تأییدشده** در **34 صفحه**.
- خروجی‌های مرورگر دارای فایل PNG و هش معتبر: **21** (تعداد خروجی‌ها، نه تعداد تصاویر مرجع تکمیل‌شده).
- خروجی‌های ثبت‌شده به‌صورت GitHub Actions Artifact: **21**.
- خروجی‌هایی که نمایش در همین گفتگو برایشان ثبت شده: **3**.
- PNGهای دارای Git blob ثبت و تأییدشده: **0**.
- خروجی‌های دارای تأیید نهایی مستقل مالک: **0**.
- نگاشت یک‌به‌یک اثبات‌شده از خروجی مرورگر به شناسه تصویر مرجع: **0/212**.

### راهنمای تیک‌ها

- `[x]` یعنی شواهد همان ستون موجود است؛ `[ ]` یعنی انجام‌شدن آن تأیید نشده است. خالی‌بودن ستون به معنی شکست فنی نیست.
- ستون «Google Docs» تنها **تأیید طرح مرجع** است؛ به‌هیچ‌وجه معادل تأیید خروجی کدنویسی‌شده نیست.
- «ثبت در GitHub Actions» با «وجود فایل PNG در Git» یکسان نیست. Artifact ممکن است بر اساس Retention منقضی شود.
- تنها زمانی برای یک تصویر مرجع، ستون ساخت/ثبت تیک می‌خورد که خروجی **با همان `screenshotId`** و شواهد معتبر یک‌به‌یک ثبت شود.
- تمام خروجی‌های فعلی غیرعملیاتی هستند. وضعیت CI/Governance و Human Gate مستقل است.

## دستور به‌روزرسانی در هر گام

۱. خروجی واقعی را بساز و **در همین گفتگو** نمایش بده.
۲. فایل PNG و SHA-256 و اندازه را کنترل کن؛ در GitHub ثبت کن و شناسه Run/Artifact یا مسیر Blob معتبر بگیر.
۳. یک رکورد با شناسه خروجی یکتا به `apps/web/contracts/web-p0-image-evidence.json` اضافه کن؛ `shownInConversation` را فقط پس از نمایش واقعی `true` کن.
۴. اگر و فقط اگر نگاشت قطعی با یکی از تصاویر مرجع وجود دارد، فیلد `designScreenshotId` را اضافه کن؛ در غیر این صورت این فیلد را خالی بگذار.
۵. چک‌لیست را با `node apps/web/scripts/web-p0-image-checklist.mjs --write` بازتولید کن. CI با `--check` از قدیمی‌ماندن آن جلوگیری می‌کند.
۶. **تأیید ظاهر خروجی، رفع Governance و مجوز ادغام** جداگانه انجام می‌شوند؛ تیک ساخت/ثبت به معنی تکمیل پروژه نیست.
